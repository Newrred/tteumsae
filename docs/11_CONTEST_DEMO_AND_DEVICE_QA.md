# 공모전 90초 데모와 실기기 제출 게이트

> **상태: 레거시 데모 기준.** 이 문서는 순수 여유시간·최대 5곳 흐름을 설명하므로
> 신규 도착 마감 알파의 제출 기준으로 사용하지 않는다. Gate 2 구현 후 한 곳 선택,
> 최대 체류시간과 출발 권장시각 기준으로 다시 작성한다.

기준 흐름: `HOME → LOCATION → TIME → CONDITIONS → LOADING → RESULTS → DETAIL`

이 문서는 공모전 제출 직전의 짧은 시연과 실기기 합격 여부만 기록한다. 전체
회귀 항목과 알려진 문제는 [QA와 알려진 문제](08_QA_AND_KNOWN_ISSUES.md)를
따른다.

## 1. 시연에서 지켜야 할 현재 제품 경계

- 사용자는 기본 출발지→목적지 이동시간을 제외하고 경유에 쓸
  `순수 여유시간(extraTimeMinutes)`을 15~1,440분으로 입력한다.
- 안전여유는 순수 여유시간보다 작은 값이어야 한다.
- 추천 시간 조건은 다음 한 가지 공식으로 설명한다.

```text
우회 주행시간 + 기본 머무름 + 안전여유 ≤ 입력한 순수 여유시간
```

- 순수 여유시간은 목적지까지의 전체 이동시간이 아니다. 기본 경로 시간은
  카카오 차량 경로로 별도 계산한다.
- 붉은 영역은 실제 등시간선이 아니라 기준 경로 주변의 `탐색 후보 범위`다.
- 결과 상단 시간은 현재 선택 경유지를 포함한 경로 시간과 장소별 기본
  머무름을 합친 값이다. 실패 시 추정값으로 대체될 수 있다.
- 실제 최종 경로와 도착시간은 카카오맵에서 다시 계산한다.

## 3. 90초 골든 데모 대본

말보다 화면 동작을 우선한다. 아래 장소명과 수치는 리허설에서 실제로 나온
값만 읽는다.

| 시간 | 화면 동작 | 발표 문장 |
|---:|---|---|
| 0~8초 | 홈 지도와 `목적지 검색`을 보여준다 | “틈새는 강원도로 이동하는 길에, 남는 여유시간으로 들를 장소를 찾는 관광 앱입니다.” |
| 8~20초 | 목적지 검색을 열고, 현위치 출발지와 검증된 강원도 목적지를 선택한다 | “출발지는 현재 위치로 잡고, 강원도 안의 최종 목적지를 정합니다.” |
| 20~32초 | TIME에서 리허설한 15~1,440분 순수 여유시간과 그보다 작은 안전여유를 입력한다 | “기본 이동시간은 카카오 경로로 계산하고, 사용자는 경유에 쓸 순수 여유시간만 입력합니다. 우회시간과 머무름, 안전여유의 합이 이 입력 안에 드는 장소만 남깁니다.” |
| 32~40초 | `산책·관광`, `카페` 등 리허설한 관심사를 선택한다 | “지금 원하는 활동을 복수로 골라 여행 상황에 맞지 않는 후보를 줄입니다.” |
| 40~55초 | 로딩 후 결과 지도, 기본 경로, 파란 후보 핀과 카드를 보여준다 | “관광공사 TourAPI 장소를 정제하고, 카카오의 실제 차량 기준 경로 주변 후보와 결합합니다. 붉은 영역은 탐색 후보 범위입니다.” |
| 55~68초 | 카드 또는 핀에서 후보 한 곳을 추가하고 상단 `경유지 1/5`, 시간·거리 갱신을 보여준다 | “후보를 경유지로 추가하면 카카오 경로를 다시 계산합니다. 경유지는 최대 다섯 곳까지 선택할 수 있습니다.” |
| 68~78초 | 장소 상세에서 실제 이미지, 운영정보·태그·기본 머무름을 짧게 보여주고 결과로 돌아온다 | “공공데이터의 이미지와 방문 정보를 함께 보여주고, 불명확한 운영정보는 확인이 필요하다고 표시합니다.” |
| 78~90초 | 결과 CTA로 카카오맵을 열어 출발지·경유지·최종 목적지를 보여준다 | “선택한 경유지와 최종 목적지를 카카오맵으로 넘겨 실제 안내를 이어갑니다.” |

발표 중 사용하지 않을 표현:

- `100% 안전`, `절대 늦지 않음`, `AI 개인화`, `최적 경유 순서`
- 검증하지 않은 전체 장소 수, 사용자 수, 시간 절감률 또는 지역경제 효과
- 붉은 후보 영역을 `실제 이동 가능 영역` 또는 `등시간선`이라고 부르는 표현

## 4. 90초 시연 합격 조건

- [ ] 새 설치 또는 동일 초기상태에서 대본을 90초 안에 한 번에 완료했다.
- [ ] 화면에 테스트용 하드코딩 수치나 개인정보가 보이지 않았다.
- [ ] 실제 TourAPI 장소 이미지·이름·방문정보를 최소 한 건 보여줬다.
- [ ] 순수 여유시간과 안전여유를 입력하고 두 값의 의미를 정확히 설명했다.
- [ ] `우회+기본 머무름+안전여유≤순수 여유시간` 공식을 같은 용어로 설명했다.
- [ ] 후보 추가 후 `경유지 1/5`와 경로 요약이 갱신됐다.
- [ ] 카카오맵에 출발지·선택 경유지·최종 목적지가 모두 표시됐다.
- [ ] 네트워크 실패를 성공처럼 숨기거나 추정값을 실시간값이라고 설명하지 않았다.
- [ ] 같은 APK의 백업 영상과 다운로드 QR/URL을 준비했다.

## 6. 공모전 제출 게이트

다음 중 하나라도 충족하지 못하면 라이브 시연보다 수정 또는 녹화 데모를
우선한다.

- [ ] `LOC-01~04`, `TIME-01~05`, `ROUTE-00·01·05·08`, `ERR-01·03`, `BACK-01·02` 통과
- [ ] 최소 두 종류의 실제 Android 기기에서 핵심 흐름 통과
- [ ] 최신 커밋·앱 버전·APK SHA-256과 QA 기록 일치
- [ ] 백엔드 자동 테스트 결과와 실기기 QA 결과를 서로 구분해 기록
- [ ] 발견된 실패를 삭제하지 않고 제출 전 조치·우회·잔여 위험으로 분류
- [ ] 제출 APK, QR/URL, 백업 영상이 같은 버전인지 확인
