# 공간 정보 보강 로드맵

기준일: 2026-09-07

이 문서는 틈새의 장소 정보를 늘릴 때 무엇을 먼저 붙이고, 어떤 판단에 사용할지를 정한다.
장소 정보가 많아 보이는 것보다 `지금 이 경로에서 들를 수 있는가`를 더 정확하고 빠르게
판단하게 하는 정보를 우선한다.

## 적용 원칙

- 지도 핀과 추천 목록은 가볍게 유지하고, 상세 전용 정보는 장소 단건 API에서만 제공한다.
- 공급자 원문은 서버에 보존하되 앱에는 정규화·검증된 최소 필드만 공개한다.
- 혼잡·날씨처럼 변하는 값은 확정 표현이 아니라 기준시각이 있는 보조 신호로 표시한다.
- 접근성은 모든 사용자에게 필수 단계로 묻지 않고 선택 필터와 상세 정보로 제공한다.
- 목적지 주차와 주변 공영주차장을 같은 값으로 합치지 않는다.
- 새 키·활용신청·과금이 필요한 단계는 코드 준비와 운영 활성화를 분리한다.

## 순차 적용

### 1. TourAPI 반복 상세·사진 권리 정보

상태: 코드 완료, 운영 적용 대기.

- 기존 `KorService2` 키로 `detailInfo2`를 동기화한다.
- `infoname/infotext`, `subname/subdetailoverview`처럼 제목·설명이 모두 있는 항목만
  HTML 제거와 중복 제거 후 `detail_items`로 공개한다.
- `detailImage2`의 URL, 이미지명, `cpyrhtDivCd`를 보존한다.
- 상세 대표 사진 URL과 메타데이터 URL이 일치할 때만 공공누리 유형을 표시한다.
- 목록·추천에는 두 배열을 넣지 않고 `/api/places/{id}`에서만 제공한다.

운영 적용 전 migration 007과 Preview smoke가 필요하다. 한국관광공사는 KorService2가
공통·소개·반복·이미지 등 15종 정보를 제공하고 사진에는 공공누리 제1·3유형이 포함된다고
명시한다: [공공데이터포털 공식 명세](https://www.data.go.kr/tcs/dss/selectApiDataDetailView.do?publicDataPk=15101578).

### 2. 도보 경로 정확도

상태: 코드 완료, Preview 활성화·실응답 확인 대기.

- `KAKAO_WALK_ROUTE_ENABLED=true`일 때 카카오맵 도보 경로의 전체·구간별 시간, 거리와
  경로선을 추천 계산에 사용한다. 탐색 옵션은 `ACCESSIBLE`이다.
- 차량과 마찬가지로 직행 경로로 corridor를 만들고 후보를 최대 8곳만 실제 계산한다.
- 기존 Android와 저수준 경로 모델의 호환을 위해 `legs[].drivingMinutes` 필드명은 유지하되
  provider는 `KAKAO_MAP_WALK`로 구분한다.
- 비활성 상태에서는 기존 `ESTIMATE`, 활성 상태에서 쿼터·응답·경로 문제가 생기면
  `ESTIMATE_FALLBACK`과 사용자 경고를 반환한다.
- 일일 무료량 1,000건 중 서버 hard stop은 800건, 운영 경고선은 700건으로 둔다.

공식 계약은 WGS84 좌표, 경유지 최대 5개, `totalTime` 초·`totalDistance` 미터와
`steps[].path.points`를 제공한다. 무료 쿼터는 개발자 계정에서 첫 번째로 활성화한
카카오맵 앱에만 적용되며 추가 쿼터는 건당 10원이다.
[카카오맵 도보 경로 공식 문서](https://developers.kakao.com/docs/ko/kakaomap/rest-api),
[카카오 쿼터 공식 문서](https://developers.kakao.com/docs/ko/getting-started/quota)

### 3. 관광지 혼잡 예측

상태: 별도 활용신청 필요.

한국관광공사 관광지 혼잡도 예측 API를 서버 배치로 수집한다. 앱 요청마다 원천 API를
호출하지 않고 Supabase에 장소·예측시각·기준시각·상대 혼잡값을 저장한다. 첫 UI는
`한산 예상 / 보통 예상 / 혼잡 예상`의 보조 문구만 제공하며 추천 점수에는 바로 넣지 않는다.
[공식 데이터](https://www.data.go.kr/data/15128555/openapi.do)

### 4. 도착 무렵 날씨

상태: 별도 활용신청·격자 변환 필요.

기상청 단기예보의 5km 격자값을 장소 좌표와 도착 예상시각에 맞춘다. 야외 활동으로 확인된
장소에만 강수·기온·바람을 간단히 표시하고, 추천 제외 기준은 Gate 3 관찰 뒤 결정한다.
[기상청 단기예보 공식 데이터](https://www.data.go.kr/data/15084084/openapi.do)

### 5. 접근성 정보

상태: `KorWithService2` 별도 활용신청 필요.

주출입구, 휠체어, 장애인 화장실, 시청각 안내, 영유아 편의 등 실제 제공 필드를 정규화한다.
기본 경로에 새 필수 단계를 추가하지 않고, 선택 필터와 장소 상세에만 노출한다.

### 6. 주변 공영주차장

상태: 정적 데이터 적재 설계 필요.

전국주차장 표준데이터의 좌표·운영시간·요금·주차면수를 주기 적재하고 장소 반경 검색으로
연결한다. TourAPI의 장소 자체 주차 문구와 분리해 `주변 공영주차장` 섹션으로 제공한다.
[공식 데이터](https://www.data.go.kr/data/15012896/openapi.do)

### 7. 사용자 근거 뒤 재평가

체류시간 모델, Tmap 기반 연관관광지, 두루누비 코스는 정보량은 늘리지만 현재 한 곳 경유
결정의 정확도를 바로 높인다는 근거가 약하다. Gate 3에서 장소 선택 실패 원인이 콘텐츠 부족인지
확인한 뒤 적용한다.

## 완료 기준

- 새 정보가 없거나 원천 API가 실패해도 기존 추천·상세가 정상 동작한다.
- 원문 HTML, 비정상 URL, 비밀키는 공개 API와 Android 저장 스냅샷에 들어가지 않는다.
- 매 단계마다 Backend test/check, Android unit/lint/assembleDebug를 통과한다.
- 외부 공급자 값은 공식 문서, 샘플 응답, Preview smoke를 모두 확인한 뒤 Production에 올린다.
